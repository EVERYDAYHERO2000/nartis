# Nartis RF: чтение показаний счётчика Нартис по радиоканалу 433 МГц

Прошивка для **ESP32-C3** с радиомодулем **CC1101**. Устройство сопрягается со счётчиком электроэнергии **Нартис И100 / И300** по его радиоинтерфейсу RF433, то есть работает так же, как выносной дисплей **Нартис Д101**. Затем оно регулярно опрашивает счётчик по протоколу DLMS/COSEM и отдаёт показания:

- в собственном **веб-интерфейсе**;
- через **REST API (JSON)**: для Home Assistant и любых других систем.

Wi-Fi настраивается через точку доступа, а серийный номер счётчика, канал и интервал опроса — в веб-интерфейсе. Перепрошивка для этого не нужна.

## Возможности

- Сопряжение со счётчиком: устройство само получает ключ сессии. Сессия хранится во flash, поэтому после перезагрузки повторное сопряжение не нужно.
- Опрос по расписанию (5, 10 или 30 минут): мощность, напряжения и токи по фазам, энергия суммарно и по тарифам, частота сети.
- Первая настройка через точку доступа `nartis-setup` с captive-portal.
- Если сохранённая Wi-Fi сеть недоступна, точка доступа для настройки поднимается снова.
- REST API для интеграций и готовая интеграция для Home Assistant.

## Совместимость

| Счётчик | Выносной дисплей | Поддержка |
|---|---|---|
| Нартис И100 / И300 с RF433 | Д101 | да |
| Нартис с RF433-2 (в основном выпуск 2024 г. и новее) | Д101-2 | нет, это другой протокол, см. [latonita/esphome-nartis-rf-2-meter](https://github.com/latonita/esphome-nartis-rf-2-meter) |

Проверено на трёхфазном счётчике Нартис И300 с дисплеем Д101.

## Оборудование

| Модуль | Что использовалось | Примечание |
|---|---|---|
| Микроконтроллер | ESP32-C3 Super Mini | USB-C, встроенный стабилизатор 3.3 В |
| Радиомодуль | CC1101 433 МГц, Ebyte **E07-M1101D** | 8 выводов (разъём 2×4), разъём SMA |
| Антенна | на 433 МГц | подключается к SMA модуля |
| Питание | USB 5 В | один кабель для всего устройства |

Подойдёт и другой модуль CC1101, но **именно на 433 МГц** (бывают версии на 315/868/915 МГц).

## Схема подключения

Выводы разъёма E07-M1101D:

```
 2 VCC    4 CSN    6 MOSI   8 GDO2
 1 GND    3 GDO0   5 SCK    7 MISO
```

| E07-M1101D | Сигнал | ESP32-C3 Super Mini |
|---|---|---|
| 1 | GND | G |
| 2 | VCC | **3V3** |
| 3 | GDO0 | GPIO3 |
| 4 | CSN | GPIO7 |
| 5 | SCK | GPIO4 |
| 6 | MOSI | GPIO6 |
| 7 | MISO | GPIO5 |
| 8 | GDO2 | не подключается |

```
            USB 5V
              │
   ┌──────────┴──────────┐            ┌──────────────────┐
   │  ESP32-C3 Super Mini │            │   E07-M1101D     │
   │                      │            │   (CC1101)       │
   │                 3V3 ─┼────────────┼─ 2 VCC           │
   │                   G ─┼────────────┼─ 1 GND           │
   │               GPIO4 ─┼────────────┼─ 5 SCK           │
   │               GPIO6 ─┼────────────┼─ 6 MOSI          │
   │               GPIO5 ─┼────────────┼─ 7 MISO          │
   │               GPIO7 ─┼────────────┼─ 4 CSN           │
   │               GPIO3 ─┼────────────┼─ 3 GDO0          │
   └──────────────────────┘            └────────┬─────────┘
                                                │ SMA
                                           антенна 433 МГц
```

**Питание.** CC1101 работает от 1.8–3.6 В, поэтому VCC модуля подключается **только к 3V3**, не к 5V. Логические уровни ESP32-C3 тоже 3.3 В, преобразователь уровней не нужен. Всё устройство питается от одного USB-кабеля, воткнутого в ESP32-C3. Модуль потребляет около 30 мА, встроенный стабилизатор платы с этим справляется.

Пины задаются в [`firmware/main/meter.cpp`](firmware/main/meter.cpp) (`PIN_SCK`, `PIN_MISO`, `PIN_MOSI`, `PIN_CSN`, `PIN_GDO0`).

## Сборка и прошивка

Нужен [ESP-IDF](https://docs.espressif.com/projects/esp-idf/en/latest/esp32c3/get-started/) **v5.5** (проверено на v5.5.5).

```bash
cd firmware
idf.py set-target esp32c3
idf.py build
idf.py -p /dev/cu.usbmodemXXXX flash monitor
```

На Linux порт обычно называется `/dev/ttyACM0`, на Windows — `COMx`. Если плата не входит в режим прошивки, держите кнопку BOOT при подключении USB.

Веб-интерфейс (`web/`) встраивается в прошивку при сборке, отдельно его загружать не нужно.

## Первая настройка

1. Включите устройство. Без сохранённого Wi-Fi оно поднимает открытую точку доступа **`nartis-setup`**.
2. Подключитесь к ней с телефона или ноутбука. Страница настройки откроется сама, иначе откройте `http://192.168.4.1`.
3. **Настройки → Wi-Fi**: выберите сеть, введите пароль, нажмите «Подключить». Устройство перезагрузится и подключится к сети.
4. Найдите IP-адрес устройства в списке клиентов роутера и откройте его в браузере.
5. **Настройки → счётчик**: введите **серийный номер счётчика** (12 цифр с шильдика), при необходимости канал и интервал опроса, нажмите «Сохранить». Устройство перезагрузится.
6. Примерно через 40 секунд устройство сопряжётся со счётчиком и покажет первые показания.

Устройство должно находиться в зоне радиоприёма счётчика.

## Веб-интерфейс

- **Показания**: текущие значения, состояние сопряжения и время последнего обновления. Страница обновляется сама.
- **Настройки**: Wi-Fi, серийный номер, канал (авто или CH0–CH3), интервал опроса, адрес API.

## REST API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/readings` | текущие показания |
| GET | `/api/status` | режим сети, IP, RSSI |
| GET | `/api/config` | серийный номер, канал, интервал |
| POST | `/api/config` | `{"meter_serial":"…","channel":"auto","update_interval":600}`, затем перезагрузка |
| GET | `/api/wifi/scan` | список Wi-Fi сетей |
| POST | `/api/wifi` | `{"ssid":"…","password":"…"}`, затем перезагрузка |

Пример ответа `GET /api/readings`:

```json
{
  "name": "nartis",
  "online": true,
  "paired": true,
  "serial": "000000000000",
  "age": 42,
  "values": [
    {"label": "Мощность", "obis": "1.0.1.7.0.255", "unit": "Вт", "decimals": 0, "value": 2125, "stale": false},
    {"label": "Напряжение L1", "obis": "1.0.32.7.0.255", "unit": "В", "decimals": 1, "value": 220.4, "stale": false}
  ]
}
```

- `paired`: устройство сопряжено со счётчиком;
- `age`: сколько секунд назад получены показания (`null`, если ещё не было);
- `value`: значение уже в единицах `unit`, либо `null`, если значение ещё не прочитано.

### Значения

| Поле `label` | OBIS | Единица |
|---|---|---|
| Мощность | `1.0.1.7.0.255` | Вт |
| Напряжение L1 / L2 / L3 | `1.0.32.7.0.255` / `1.0.52.7.0.255` / `1.0.72.7.0.255` | В |
| Ток L1 / L2 / L3 | `1.0.31.7.0.255` / `1.0.51.7.0.255` / `1.0.71.7.0.255` | А |
| Энергия | `1.0.1.8.0.255` | кВт·ч |
| Тариф 1 / Тариф 2 | `1.0.1.8.1.255` / `1.0.1.8.2.255` | кВт·ч |
| Частота | `1.0.14.7.0.255` | Гц |

Счётчик не передаёт масштаб величин, поэтому множители заданы в прошивке, в таблице `DEFS` в [`firmware/main/meter.cpp`](firmware/main/meter.cpp). Там же меняется набор опрашиваемых OBIS-кодов.

## Интеграция с Home Assistant

В репозитории есть пользовательская интеграция [`custom_components/nartis`](custom_components/nartis). Она добавляет устройство «Нартис» со всеми сенсорами, настраивается через интерфейс Home Assistant и опрашивает локальный API устройства без облака и MQTT. Проверена на Home Assistant 2026.10.

### Установка

**Через HACS:** HACS → меню ⋮ → «Пользовательские репозитории» → адрес `https://github.com/EVERYDAYHERO2000/nartis`, категория «Интеграция» → установить **Nartis RF Meter** → перезапустить Home Assistant.

**Вручную:** скопируйте папку `custom_components/nartis` в `config/custom_components/` вашего Home Assistant и перезапустите его.

### Подключение

**Настройки → Устройства и службы → Добавить интеграцию → Nartis RF Meter**, затем введите IP-адрес устройства. Интеграция проверит связь и создаст устройство «Нартис <серийный номер>».

### Сенсоры

| Сенсор | Единица | Класс |
|---|---|---|
| Мощность | W | power |
| Напряжение L1 / L2 / L3 | V | voltage |
| Ток L1 / L2 / L3 | A | current |
| Энергия, Энергия тариф 1 / тариф 2 | kWh | energy, `total_increasing` |
| Частота | Hz | frequency |
| Сопряжение со счётчиком (диагностика) | вкл/выкл | connectivity |
| Последнее чтение (диагностика) | дата/время | timestamp |
| Сигнал Wi-Fi (диагностика, по умолчанию выключен) | dBm | signal_strength |

Сенсоры энергии можно сразу добавить в панель «Энергия». Если в прошивке изменить набор OBIS-кодов, незнакомые интеграции значения появятся как отдельные сенсоры с названием и единицей из прошивки.

В параметрах интеграции задаётся, как часто Home Assistant опрашивает устройство (по умолчанию 60 секунд). Сам счётчик устройство читает с интервалом из своего веб-интерфейса, поэтому новые значения появляются с этой периодичностью.

### Без интеграции: REST-сенсоры в YAML

Если пользовательскую интеграцию ставить не хочется, те же данные можно получить штатными REST-сенсорами. Добавьте в `configuration.yaml`, указав IP-адрес вашего устройства:

```yaml
rest:
  - resource: http://192.168.0.50/api/readings
    scan_interval: 60
    sensor:
      - name: "Нартис мощность"
        unique_id: nartis_power
        value_template: "{{ (value_json['values'] | selectattr('obis', 'eq', '1.0.1.7.0.255') | first)['value'] }}"
        availability: "{{ (value_json['values'] | selectattr('obis', 'eq', '1.0.1.7.0.255') | first)['value'] is not none }}"
        unit_of_measurement: W
        device_class: power
        state_class: measurement

      - name: "Нартис энергия тариф 1"
        unique_id: nartis_energy_t1
        value_template: "{{ (value_json['values'] | selectattr('obis', 'eq', '1.0.1.8.1.255') | first)['value'] }}"
        availability: "{{ (value_json['values'] | selectattr('obis', 'eq', '1.0.1.8.1.255') | first)['value'] is not none }}"
        unit_of_measurement: kWh
        device_class: energy
        state_class: total_increasing
```

Остальные величины подключаются так же, по OBIS-коду из таблицы выше.

## Особенности

- **Мощность Wi-Fi передатчика 8.5 dBm.** На платах ESP32-C3 Super Mini при мощности по умолчанию (~20 dBm) сигнал искажается: устройство видит сети, но роутер не принимает его кадры, а точку доступа не видно. Значение задаётся константой `TX_POWER_QDBM` в [`firmware/main/net.c`](firmware/main/net.c). На других платах её можно увеличить.
- Энергию счётчик передаёт в Вт·ч, прошивка пересчитывает её в кВт·ч.
- Один цикл чтения занимает около 30 секунд. Показания хранятся в памяти, поэтому после перезагрузки они появляются со следующим циклом (через ~40 секунд после старта).
- После смены серийного номера, канала или интервала устройство перезагружается.
- Показания читаются пачками по 5 значений, а ответ счётчика не содержит OBIS-кодов. Иногда счётчик повторно присылает ответ на предыдущую пачку, и без защиты, например, напряжения попали бы в сенсоры энергии и тарифов. Поэтому прошивка сверяет тип каждого значения с ожидаемым (поле `dtype` в таблице `DEFS`) и отбрасывает чужие ответы.

## Структура репозитория

```
firmware/                    проект ESP-IDF
  main/
    main.c                   запуск
    net.c                    Wi-Fi: точка доступа для настройки, подключение к сети, captive-portal DNS
    web.c                    HTTP-сервер, веб-интерфейс и REST API
    settings.c               настройки в NVS
    meter.cpp                связка радио-стека с API, таблица OBIS-кодов, пины CC1101
  components/nartis_rf/      радио-стек: CC1101, сопряжение, AES-128-GCM, DLMS
    src/                     код компонента FerrumLogic/esphome-nartis-rf-meter-cc1101

  sdkconfig.defaults

custom_components/nartis/    интеграция для Home Assistant
hacs.json                    описание для установки через HACS
```

## Использованные проекты

- **[latonita/esphome-nartis-rf-meter](https://github.com/latonita/esphome-nartis-rf-meter)** (MIT, Anton Viktorov): исходная реализация протокола счётчиков Нартис RF433. Это сопряжение, кадры, CRC, AES-128-GCM и DLMS/COSEM, оригинально для радиомодуля CMT2300A.
- **[FerrumLogic/esphome-nartis-rf-meter-cc1101](https://github.com/FerrumLogic/esphome-nartis-rf-meter-cc1101)**: порт этого компонента на радиомодуль CC1101. Его код перенесён в [`firmware/components/nartis_rf/src`](firmware/components/nartis_rf/src) почти без изменений (версия указана в `UPSTREAM.txt`). Добавлены только прослойка вместо ESPHome, метод `is_paired()` и проверка типов значений в ответах счётчика. Последняя не даёт записать ответ одной пачки показаний в сенсоры другой (подробнее в разделе «Особенности»).
- **Драйвер CC1101 на базе библиотеки panStamp** (panStamp, Tyler Sommer, Daniel Berenguer; LGPL-3.0) в составе компонента FerrumLogic: [`cc1101_vendored.c`](firmware/components/nartis_rf/src/cc1101_vendored.c).
- **[ESP-IDF](https://github.com/espressif/esp-idf)** (Espressif, Apache-2.0).
- **[latonita/esphome-nartis-rf-2-meter](https://github.com/latonita/esphome-nartis-rf-2-meter)**: решение для счётчиков с RF433-2 / Д101-2, которые этот проект не поддерживает.
